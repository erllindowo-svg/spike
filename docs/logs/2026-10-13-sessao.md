## 1. Repositório corrompido após travamento do PC

Sintoma em qualquer comando Git:

```
error: object file .git/objects/a5/ed8b0d0c2d4fb7ba062b6fc11e7ba815553f87 is empty
fatal: bad object HEAD
```

Fatos levantados (somente leitura):

- `.git/refs/heads/feat/persistence` apontava para `a5ed8b0`, um objeto vazio.
- 39 arquivos vazios em `.git/objects`: o commit, as árvores e os blobs
  gravados às 19:57, no momento do travamento.
- O reflog terminava em `87f9ccc` (troca para MongoDB), que estava íntegro.
- `.git/COMMIT_EDITMSG` guardava a mensagem do commit perdido
  ("feat: choose demo or MongoDB data for the whole app with DATA_SOURCE").
- Working tree: 19 arquivos alterados em relação a `87f9ccc`. Para cada
  arquivo do índice, `git hash-object <arquivo>` coincidiu com o hash
  registrado. Ou seja, o conteúdo na pasta era idêntico ao que ia para o commit.

Reparo:

```bash
cp -a .git <scratchpad>/git-backup-pre-repair   # backup temporário (some ao reiniciar)
find .git/objects -type f -empty -delete         # objetos vazios não guardam nada
git update-ref refs/heads/feat/persistence 87f9ccc
rm .git/index && git reset -q                    # índice refeito a partir de 87f9ccc
git add -A && git commit -F <mensagem original>  # → 8cb096f
```

Verificações antes do commit recriado:

```
pnpm test          → Test Files 8 passed (8) · Tests 83 passed (83)
pnpm lint          → sem avisos
pnpm typecheck     → ok
pnpm format:check  → All matched files use Prettier code style!
pnpm build         → ok
```

Resíduo: `git fsck --full` acusa
`HEAD: invalid reflog entry a5ed8b0…` e o mesmo em
`refs/heads/feat/persistence`. A limpeza do reflog foi bloqueada para o agente
por ser irreversível; ficou como decisão do usuário.
